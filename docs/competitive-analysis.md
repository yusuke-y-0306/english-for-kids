# 世界の子ども向け英語アプリ調査 — English for Kids 改善提案

最終更新: 2026-11-23 / 調査: Steve Lobs

## 0. 結論（先に3行）

1. 世界の勝ち筋は「コンテンツ量」ではなく **学習の道（カリキュラム）＋復習の仕組み＋関係性（キャラクター）**。
2. このアプリは **発音・プライバシー・日本語UI** で既に差別化できている。足りないのは **毎日開く理由** と **覚えたかどうかを測る仕組み**。
3. 次の一手はコンテンツ追加ではなく、既に貯まっている進捗データを使う **復習エンジンと5分の導線**。ここを先に作ると、以後のコンテンツ追加が「効くかどうか」を数字で判断できる。

---

## 1. 調査方法と限界

- 対象: 世界で利用されている子ども向け英語・読み書きアプリ 10 本＋日本語市場 3 本。
- 一次情報: App Store の説明文・評価数（iTunes Search API、2026-11-23 取得。国は US、日本向けは JP）、各社公式サイト。
- 二次情報: 公表されている利用者数・ダウンロード数（各社の自己申告。第三者検証はしていない）。
- **限界**: 実際の学習効果（RCT）は公開されていないものが多い。ここでは「プロダクト設計の型」を比較しており、効果量の比較ではない。価格・機能は変更されるため、意思決定時に再確認すること。

## 3. 勝ち筋の共通パターン（8つ）

1. **「道」がある** — メニューではなく「次にやる1つ」が決まっている。Khan の Kodi、ABCmouse の Learning Path、Reading Eggs のマップ。
2. **読む力の梯子** — 文字の音（フォニックス）→ CVC → サイトワード → デコーダブル絵本。Duolingo ABC / Reading Eggs / Starfall / Teach Your Monster は必ず持つ。
3. **キャラクターとの関係** — Kodi、Duo、ABCmouse、モンスター。名前・感情・反応があると「また会いたい」が継続になる。
4. **1回5〜15分の区切り** — 短い、終わりが明確、最後に必ず祝う。
5. **報酬の二層** — 即時（音・スタンプ・アニメ）と長期（図鑑・レベル・連続記録）。即時だけだと飽き、長期だけだと続かない。
6. **保護者の可視化** — 週次レポート、つまずき語、利用時間。子ども向け画面とは別に持つ。
7. **適応と復習** — 配置テスト、難易度の自動調整、間隔を空けた再出題。ここが「やった感」と「身についた」を分ける。
8. **音が第一** — 未就学児は文字を読めない。音声・歌・チャンツが入口。オフライン再生も強い。

## 4. 現状の棚卸し（リポジトリの事実）

- 機能: フラッシュカード / 単語ならべかえ / 発音練習 / クイズ4レベル / 進捗 / パスキーログイン。
- コンテンツ: 16 カテゴリ **200 語**（うちサイトワード 40）、ならべかえ 11 タスク、文法 23 問。絵本・歌・チャンツ・フォニックスは無し。
- 音声: 全単語に mp3。Service Worker は `/audio/` のみキャッシュ（アプリ本体はオフライン不可）。
- 発音: 端末内 WASM（Moonshine）＋編集距離で3段階。音声・認識テキストはサーバに送らない。**単語単位のみ**。
- 進捗: 日次（クイズ/発音/カード）、単語別 `correct/wrong/lastAt`、カード閲覧、ストリーク、最大400日。**保存はあるが、出題に使っていない**。
- クイズ: 毎回ランダム。難易度は子どもが選ぶ。習得度による出し分けは無し。
- ベストスコア: localStorage のみ（端末を変えると消える）。
- 認証/安全: パスキー、署名 cookie、CSP、COOP/COEP、広告なし。**子ども向けとして強い**。
- 検証: CI 10 項目、unit/api 29 ファイル。ブラウザ E2E と `npm run verify` は PR #114（未マージ）。学習行動の計測（L4）は未着手。

### 強み（残すべき差別化）

- **声を外に出さない**（クラウド ASR を使わない）。日本の保護者に説明しやすい。
- **広告なし・外部リンクなし・パスキー**。安全性は海外大手と同等以上。
- **ひらがな UI ＋ 音声 ＋ 絵文字**。未就学児が一人で触れる。
- **軽い**。ビルドも実行もローカルで完結し、改善ループを回しやすい。

## 5. スコアカード（0〜3）

| 軸 | 点 | 根拠 |
| --- | --- | --- |
| 音声中心の UI | 3 | 全語に音声、ひらがな、絵文字 |
| 安全性・プライバシー | 3 | パスキー、ローカル ASR、広告なし、CSP |
| 発話 | 2 | 単語は強い。文・最小対・音素フィードバックが無い |
| 動機づけ | 2 | ストリークと星はある。図鑑・キャラ・サーバ保存が無い |
| 読む力の梯子 | 1 | サイトワードは追加済み。フォニックスと絵本が無い |
| 学習の道 | 1 | メニュー型。CEFR タグはあるが進行に未使用 |
| 復習・適応 | 0 | ランダム出題。進捗データを出題に使っていない |
| 保護者 | 1 | 子ども向け進捗のみ。保護者レポート無し |

## 6. 改善提案

優先度は「子どもが毎日開くか」と「既存データで作れるか」で決めた。各項目に **受け入れ条件** を付ける（ハーネスエンジニアリングの流儀: 機械が緑/赤を言える形にする）。

### P0 — 今週〜2週間（新コンテンツ不要）

#### P0-1. 間隔反復スケジューラと「きょうの復習」キュー

- **なぜ**: 200 語あっても、ランダムでは「覚えた語」と「忘れた語」に同じ時間を使う。Reading Eggs の配置テスト、ABCmouse の適応、トド英語の一人で進む設計は、すべて「次に何を出すか」を持っている。
- **なに**: `words[wordId].correct/wrong/lastAt` から due 語を導く純粋関数。Leitner 5 箱（1日→3日→7日→14日→30日）。間違えたら箱を戻す。クイズとカードは due を優先（目安 60%）。
- **受け入れ条件**:
  - スケジューラは純粋関数で、`node --test` に決定論的なテスト（同じ入力→同じ出力、30日シミュレーション）。
  - 1 セッション内で同じ語を 2 回出さない（既存の `uniqueByEn` と同様）。
  - due が 0 のときは新規語を出す（空のセッションにしない）。
  - 既存ユーザーのデータ移行が不要（導出のみ。必要になったら `dueAt` を足す）。
- **既存 issue**: なし（新規）。#4 の進捗基盤の上に載る。

#### P0-2. 「きょうの 5分」ガイド付きセッション

- **なぜ**: ホームが5つのメニューだと、子どもは毎回「選ぶ」ことに energy を使う。勝ち筋は「次にやる1つ」。1回の長さを固定すると、習慣と計測の両方が立つ。
- **なに**: 復習3問 → 新規2語 → 発音1語 → クイズ2問（計5分）。最後に「きょうの できた」と次の約束（明日／また今度）。既存モードを順番に呼ぶだけで、新しい学習画面は作らない。
- **受け入れ条件**:
  - 1 セッション ≤ 7 分（p50）、途中離脱しても答えた分は記録（既存の #65 の冪等設計を再利用）。
  - E2E: ホーム→セッション完走→進捗に反映、の1本。
  - セッション完了率と離脱ステップを計測（P0-3）。

#### P0-3. 学習イベント計測（L4）と週次ファネル

- **なぜ**: これまでの議論どおり、ハーネスの L4（計測）が無い。改善の効果を数字で言えないと、コンテンツ追加が「作業」になる。
- **なに**: `session_start / step_complete / answer / speak_attempt / session_end` の5イベント。単語 ID・正誤・所要時間・モードだけ。音声・認識テキスト・自由記述は保存しない（#32 の方針を継承）。`docs/analytics.md` にスキーマ、純粋関数で集計。
- **受け入れ条件**:
  - イベント名と必須キーの unit テスト。未知イベントは捨てる。
  - 週次で「開始→完了」「モード別離脱」「復習正答率」が出る。
  - PII が入らないことをテストで固定（許可キーの allowlist）。

#### P0-4. ベストスコアをサーバに保存

- **なぜ**: 現在 localStorage。端末を変えると消え、保護者レポートにも使えない。小さいが「積み上がる」感に直結。
- **なに**: `data.progress.best[levelId]` に保存。`POST /api/progress/quiz` の完走時に `Math.max`。冪等。
- **受け入れ条件**: API テスト（更新・非更新・再送）、既存 localStorage からの移行は不要（初回に大きい方を採用）。

#### P0-5. 保護者ビュー最小版（#70 + #93）

- **なぜ**: 子ども向け進捗は既にあるが、保護者が「何を覚え、どこでつまずいているか」を見る口が無い。日本のおうち英語は保護者の納得が継続を左右する。
- **なに**: 合言葉で入る `/parent`。週の学習日数・新規習得語・つまずき Top5・発音 OK 率・家庭で使える一言。**音声は再生しない**（保存していない）。
- **受け入れ条件**: 合言葉ゲートの API テスト、360px で横スクロールなし、子ども画面へのリンクを置かない（誤タップ防止）。

### P1 — 2〜6週間（既存 backlog を「順番」で活かす）

| 順 | 項目 | 既存 issue | なぜこの順か |
| --- | --- | --- | --- |
| 1 | チャンツ・ライム 6〜10本＋カラオケ表示 | #89 | 最安で「音の気持ちよさ」を足せる。3〜5歳の入口 |
| 2 | 図鑑／コレクション | #92 | 既存の進捗データだけで作れる。長期報酬の器 |
| 3 | フォニックス（26文字＋CVC） | #88 | 読む力の梯子の土台。サイトワード #87 の次に効く |
| 4 | 絵本リーダー 3冊（未知語率5%以下） | #91 | フォニックスとサイトワードが揃ってから。読了感 |
| 5 | 定型フレーズ／ミニ会話 | #90 | 単語→文への橋。`GrammarChecker` を再利用 |
| 6 | 連続記録の演出（#45） | #45 | P0-3 の計測とセットで「祝う」条件を固定 |

- **チャンツ** は TTS でも「ゆっくり/普通」の2テンポ＋ポーズで成立する。歌（メロディ）は別予算。
- **フォニックス** は音素の音声が必要。既存の単語音声から切り出すのではなく、フォニーム用の短い音源を用意する（`docs/audio-assets.md` に追記）。
- **絵本** は先に「未知語率チェック」を CI に入れる（#91 の完了条件）。文章を書いてから直すのではなく、書けない条件にする。

### P1' — 差別化を伸ばす（新規）

#### P1'-1. 文レベルの発音と最小対ヒント

- **なぜ**: 単語の正誤だけでは「通じる発音」に近づかない。`ship/sheep`、`rice/lice`、`r/l`、`th/s` は日本人の定番。Speech Blubs が示すように、発話の反復は単独で価値になる。
- **なに**: 3〜5 語のフレーズ採点（既存 `scoring.ts` を単語列の差分に拡張）。どの語がずれたかを表示し、最小対のミニ練習へ。スコアは保存するが音声は保存しない。
- **受け入れ条件**: 単語列の差分の unit テスト、誤検出（言えたのに retry）率を計測、フレーズ 20 本。

#### P1'-2. コンパニオンキャラクター

- **なぜ**: 挿絵のクマとウサギはいるが、名前と関係が無い。Kodi / Duo / モンスターに負けているのは量ではなく「関係」。
- **なに**: 名前・口調・3つの反応（久しぶり／連続記録／苦手語）。ストリークと習得度に反応。図鑑の案内役も兼ねる。新しい画面は増やさない。
- **受け入れ条件**: 反応条件を純粋関数でテスト、同じ条件で繰り返さない（#45 と同じ「一度きり」設計）、音声は既存の読み上げ基盤。

#### P1'-3. 年少モード／年長モード

- **なぜ**: 3〜5歳は文字を読めず、6〜8歳は「赤ちゃん扱い」を嫌う。1つの壳で両方に最適化するのは無理。Khan Kids は年齢で世界観を変える。
- **なに**: 同じコンテンツで、年少=絵＋音＋2択、年長=文字＋4択＋文。設定は保護者が選ぶ。
- **受け入れ条件**: 年少モードで文字が必須の操作を0にする（E2E）、年長モードで幼児語を出さない。

### P2 — 四半期

- 配置テストと can-do チェック（10問、到達度の証明、修了証）。
- アプリ本体のオフライン（PWA）＋ユニット単位のダウンロード。音声だけでは車・飛行機で開けない。
- きょうだいターン制／家族ボード（安全な範囲のソーシャル）。
- 語彙 400〜600、絵本 24 冊、チャンツ 12 本。#94 の制作パイプラインを先に通す。
- 歌（メロディ付き）。最も効果が高いが、声優・作曲・権利の予算が必要。チャンツで代替してから判断。

## 7. 90日の順序（案）

| 週 | やること | 判断に使う数字 |
| --- | --- | --- |
| 1 | P0-1 スケジューラ＋P0-3 計測のスキーマ | 復習キューが空にならない、イベント欠損 0 |
| 2 | P0-2 5分セッション＋P0-4 ベスト保存 | セッション完了率、離脱ステップ |
| 3 | P0-5 保護者ビュー | 保護者の週次開封、つまずき Top5 の妥当性 |
| 4–5 | #89 チャンツ＋#92 図鑑 | 3〜5歳の再訪、図鑑閲覧 |
| 6–8 | #88 フォニックス＋#91 絵本3冊 | 文字課題の完走、絵本読了、未知語率 |
| 9–10 | #90 フレーズ＋P1'-1 文発音 | 文の正答、誤検出率 |
| 11–12 | P1'-3 年齢モード＋P1'-2 キャラ | 年齢別の継続、苦手語の再挑戦 |

**やらないこと（この90日）**: 語彙の大量追加、歌の自作、クラウド同期、課金。土台の数字が無いまま増やすと、どれが効いたか言えなくなる。

## 8. 計測（North Star とガードレール）

- **North Star**: 週あたりの学習日数（目標: 3日以上）と 5分セッションの完走率。
- **Leading**: D1/D7 再訪、1セッションの新規語数、間隔後の初回正答率、保護者ビューの週次開封。
- **Guardrail**:
  - 発音の誤検出（言えたのに retry）< 5%。
  - p95 の画面応答 < 300ms（ローカル計測）。
  - 1セッション p50 ≤ 7分、p95 ≤ 12分。
  - 保存する個人データは「単語 ID・正誤・時刻・モード」だけ。
- **学習効果の代理指標**: 同じ語を 7 日後に出したときの初回正答率。ここが上がらなければ、コンテンツを増やしても意味がない。

## 9. 真似しないこと

- 広告・外部リンク・サブスクの圧力（このアプリの強みを壊す）。
- クラウド音声認識への子どもの声の送信（保護者説明が難しくなる）。
- 説明不能なブラックボックス適応（子どもにも保護者にも理由を言えない）。
- コイン・ガチャ・無限スクロール（学習を報酬の従属物にする）。
